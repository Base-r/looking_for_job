# Начало работы

Короткая инструкция для вашей настройки. Подробная, от прежнего автора: [ИНСТРУКЦИЯ_ПОЛЬЗОВАТЕЛЯ.md](ИНСТРУКЦИЯ_ПОЛЬЗОВАТЕЛЯ.md).

## Ваши три файла

| Файл | Что в нём |
|---|---|
| [profile.md](profile.md) | Кто вы, что ищете, деньги, гео, английский и **правила оценки вакансий** для LLM. Из него же берутся факты для писем |
| [letter_style.md](letter_style.md) | Тон, длина, структура и запреты для сопроводительного письма |
| [snpr/config.toml](snpr/config.toml) | Механика: поисковые запросы, страны, минимум зарплаты, пороги скора, автоотклик, частота запуска |

Правьте как обычный текст. Изменения действуют со следующего прогона.

## Как вакансия доходит до отклика

1. Поиск на hh по запросам из `config.toml` (в названии вакансии, опыт до 3 лет, страны СНГ+).
2. Отсев без LLM: зарплата явно ниже 600 $, офис/гибрид не в Ташкенте, чёрный список.
3. LLM ставит скор 0–100 по `profile.md`.
4. Скор от 45 (`maybe_min`): LLM пишет письмо, вакансия попадает к вам на решение.
5. **Страница отбора** в браузере (открывается сама, когда джоба нашла подходящие вакансии):
   карточка со ссылкой на hh, страной, зарплатой, скором, причинами и письмом.
   - **Откликнуться** — отправить отклик с письмом из поля (письмо можно править прямо на странице);
   - **Пропустить** — больше не показывать;
   - **Позже** — скрыть до обновления страницы, вакансия остаётся в очереди;
   - **Переписать письмо** — DeepSeek пишет письмо заново.
   Ваши правки писем запоминаются: следующие письма LLM пишет с оглядкой на них.
   Закрыли вкладку — сервер страницы сам выключится через ~3 минуты.
   Консольный вариант остаётся: `python -m snpr approve` (y/n/e/q), а в конфиге
   `[approve] ui = "console"` вернёт консольное окно вместо страницы.

Автоотклик выключен (`auto_approve_min = 0`). Включить потом: поставить, например, `85`.

## Первый запуск

```powershell
# 1. Зависимости (уже установлены в .venv)
.venv\Scripts\pip.exe install -e .\hh-applicant-tool

# 2. Ключ LLM: скопировать шаблон и вписать адрес, модель, ключ
Copy-Item .env.example .env
notepad .env

# 3. Вход в hh (один раз): код из СМС, иногда капча
.venv\Scripts\python.exe -m snpr.hh_tool +998XXXXXXXXX

# 4. Пробный прогон: реальный поиск и оценка, БЕЗ откликов
.venv\Scripts\python.exe -X utf8 -m snpr sne --dry-run --mode park
#    → таблица data\dry_run_vacancies.html (скор, причины, письма, ссылки)

# 5. Боевой ручной режим: прогон, потом решение по каждой вакансии
.venv\Scripts\python.exe -X utf8 -m snpr sne --mode park
.venv\Scripts\python.exe -X utf8 -m snpr web

# Поиск сам запускается каждый день в 9:00 ([job] daily_at в config.toml;
# компьютер был выключен — запустится при включении). Страница отбора
# сама не открывается. Капча — окно с картинкой: не ввели за 20 минут —
# оценённое сохраняется, остальное оценится в следующий раз.
# То же двойным кликом: Поиск.cmd (поиск) и Отбор.cmd (страница отбора).
# Возраст вакансий: [search] min_age_days / max_age_days в config.toml
# (сейчас 0–7 дней). Разово: python -m snpr sne --mode park --min-age-days 0 --max-age-days 3
# На странице отбора диапазон «Вышла от … до … дн. назад» меняется на лету.
# Вакансии, ушедшие в архив на hh, убираются из очереди сами: Поиск проверяет
# 40 самых старых за запуск, открытая страница отбора — всю очередь раз в 15 минут.
# Выключить ежедневный поиск: python -m snpr job off (включить: job on)
# Кроме hh, бот ищет на GeekJob, Habr Career и в Telegram-каналах ([search.sources]:
# geekjob / habr / telegram = true|false, habr_queries, telegram_channels).
# Оцениваются только вакансии с подходящим названием (title_must) и нужным опытом.
# Откликаетесь на них сами: «Открыть … и скопировать письмо» (для Telegram — по
# контакту из поста), затем «Я откликнулся». Фильтр «Источник» — на обеих вкладках.
```

## Несколько резюме

Бот сам выбирает, с каким резюме откликаться:
1. Создайте и **опубликуйте** резюме на hh (с неопубликованным hh отклик не примет).
2. Узнайте его ID: `python -m snpr resumes`.
3. Добавьте в `snpr/config.toml` блок `[[resumes]]`: `id`, `title` и `use_for` — для каких вакансий оно (пример уже есть в конфиге, закомментирован).

При оценке вакансии DeepSeek выбирает подходящее резюме по `use_for`, письмо пишется с акцентом на эту роль. На странице отбора выбор виден в списке «Резюме для отклика», его можно поменять перед «Откликнуться». Первое резюме в списке — основное.

## Полезные команды

| Команда | Что делает |
|---|---|
| `python -m snpr list` | Список подходящих вакансий со ссылками + `data\vacancies.html` |
| `python -m snpr list --all --open` | Все оценённые (и отсеянные) — для калибровки порогов, сразу в браузере |
| `python -m snpr why <ссылка>` | Почему вакансия не дошла до вас |
| `python -m snpr web` | Страница отбора в браузере (`--dry-run` — без отправки) |
| `python -m snpr approve` | То же в консоли: y/n/e/q |
| `python -m snpr resumes` | Резюме на аккаунте hh: ID, опубликовано ли, есть ли в конфиге |
| `python -m snpr job status` / `off` | Состояние / выключить расписание |
| `python -m snpr nanny` | Ответы работодателей на отклики |
| `python -m snpr blacklist add <ссылка>` | Больше не показывать этого работодателя |

## Как настраивать точность

- Слишком много мусора → поднять `maybe_min` в `config.toml` или дописать анти-паттерн в `profile.md` → «Низкий скор».
- Мало вакансий → посмотреть `list --all`: если хорошие получают 50–59, снизить `maybe_min`; если их нет в поиске — добавить запрос в `[search].queries`.
- Письма не те → править `letter_style.md` или поправить пару писем через `e`: правки становятся примерами.
